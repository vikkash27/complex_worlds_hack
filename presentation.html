What We Built

An OpenReward-compatible benchmark environment that wraps a 7-stage breakfast-tray robot workflow and demonstrates that dense, semantically-shaped rewards dramatically outperform sparse success-only feedback.

🧩

The Problem

Frontier AI agents fail at tasks requiring memory, recovery, and long-horizon credit assignment. Existing benchmarks don't capture this failure mode.

Long-Horizon RL Physical AI
🍳

The Task — Breakfast Tray

  • 1 Locate items in the scene
  • 2 Clear workspace
  • 3 Pick mug & fill drink
  • 4 Place snack on tray
  • 5 Recover from mid-task disturbance
  • 6 Deliver tray to target

Dense vs Sparse Rewards

Optional Gemini-style VLM scoring at subgoal boundaries; the default path stays deterministic so demos run without API keys. After scripts/run_demo.py, see artifacts/metrics/leaderboard.json for dense vs reactive-script lifts on randomized held-out scenes.

Tech Stack

Packaged as an OpenReward environment with tool-call APIs (observe, execute_skill, score_progress). Replay GIFs, training curves, and a visual HTML report are generated automatically.

OpenReward surface

64 train · 16 val · 16 test

Four embodied task families repeat across curated seeds: breakfast tray, spill recovery, countertop cleanup, and a 30-stage humanoid hospitality chain. Task specs for hosted sessions use the same scene, horizon, and macro-step budgets as local training and scripts/benchmark_openreward.py.

Claims we can defend

Macro planning & tool policy

Success is decided by the simulator at episode end, not an LLM judge. Isaac Sim replays the same JSONL traces the OpenReward tools emit—high-fidelity visualization of decisions, not continuous-control RL inside Isaac. This complements verifier-grounded code envs and long-horizon stochastic sims elsewhere in the hackathon.

Evidence & repro

Artifacts judges can open
